Primitive Types
bool, int, float, complex, str, bytes, bytearray, None
🔢
Mental model

Every Python value is an object with three properties: identity (its address, returned by id()), type, and value. Primitive types are immutable — "changing" them always creates a new object and rebinds the name.

bool — the simplest type

Mental model

bool IS an int. True == 1, False == 0. Arithmetic works: True + True == 2. Python's truthiness system converts any object to bool implicitly via __bool__ (then __len__). Falsy: None, False, 0, 0.0, "", [], {}, set(). Everything else is truthy.

# Short-circuit evaluation — Python stops as soon as the result is known
result = None or "default"   # "default" — None is falsy
safe   = [] and risky()        # never calls risky(); [] is falsy

# Truthiness in practice
if items:          # Pythonic: "if there are items"
    process(items)

# bool is int subclass: use sum() to count truthy items
nums   = [1, 0, -1, 2, 0, 3]
truthy = sum(bool(x) for x in nums)  # == 4

int — arbitrary precision

Mental model

Python int has no overflow. Internally it uses variable-length storage. All arithmetic operators work; // is floor division (rounds toward −∞, not zero!), % is always non-negative when divisor is positive. Bitwise operators (& | ^ ~ << >>) manipulate the binary representation — essential for flags, hashing, and low-level protocols.

assert 10 // 3  == 3           # floor division
assert -10 // 3 == -4          # floor toward -∞, NOT truncation!
assert 10 % 3  == 1
assert -10 % 3 == 2           # always ≥ 0 when divisor > 0
assert 2 ** 100              # googol — no overflow

# Bitwise operations
flags = 0b0000
READ, WRITE, EXEC = 4, 2, 1   # bitmask flags
flags |= READ | WRITE            # set flags
assert flags & READ  == READ     # test flag
flags &= ~WRITE                  # clear flag
assert flags & WRITE == 0
⚠️
Gotcha — floor division vs C/Java truncation

-10 // 3 == -4 in Python (floor toward −∞), but -10 / 3 == -3 in C/Java (truncation toward 0). This matters for negative modular arithmetic, index calculations, and any port of code from other languages.

float — IEEE 754 double

Mental model

float is a 64-bit IEEE 754 double — 15–17 significant decimal digits. 0.1 cannot be represented exactly in binary (it's a repeating fraction), so 0.1 + 0.2 ≠ 0.3. Always compare with math.isclose() or round(). For money, use decimal.Decimal.

import math, decimal
assert 0.1 + 0.2 != 0.3                    # float representation error
assert math.isclose(0.1 + 0.2, 0.3)        # correct comparison
assert decimal.Decimal("0.1") + decimal.Decimal("0.2") == decimal.Decimal("0.3")
assert float("inf") > 10**300             # infinity
assert math.isnan(float("nan"))          # NaN is never equal to itself

str — immutable Unicode sequence

Mental model

Every str method returns a new string. Strings are sequences of Unicode code points — len("café") == 4. Concatenation in a loop is O(n²) because each + allocates a new string; use "".join(parts) for O(n).

bytes & bytearray

Mental model

bytes = immutable sequence of 0–255 ints. bytearray = mutable version. Both support the same methods as str plus hex(), fromhex(). Use for: binary files, network protocols, hashing inputs, zero-copy memory views.

b  = b"hello"          # bytes literal — each element is an int 0-255
ba = bytearray(b)       # mutable copy
ba[0] = 72             # 'H' — modify in place
mv = memoryview(ba)     # zero-copy slice view — no data copied
mv[1:3] = b"EL"        # modifies ba in-place through the view

# nonlocal — rebind enclosing variable
def make_counter(start: int = 0):
    count = start
    def inc(by: int = 1):
        nonlocal count     # without this: UnboundLocalError
        count += by; return count
    return inc

# Late-binding closure trap — and the fix
fns_bad  = [lambda:   i for i in range(3)]  # all return 2!
fns_good = [lambda i=i: i for i in range(3)]  # 0, 1, 2
⚠️
Gotcha — mutable default argument (evaluated ONCE at definition)

def f(x, acc=[]) — the list [] is created once and reused on every call. Accumulates state across callers. Always use def f(x, acc=None): if acc is None: acc = []. Applies to dicts, sets, and any mutable default.

OOP — All Four Pillars
Encapsulation · Inheritance · Abstraction · Polymorphism · MRO · dataclasses
🧱
🧠 Mental model — IS-A vs HAS-A vs CAN-DO

IS-A (Inheritance): subclass genuinely IS a more specific kind of the parent — Dog(Animal). Use super() + MRO. HAS-A (Composition): class uses another as a component — Car has an Engine stored as an attribute. Prefer composition when sharing behaviour, not type. CAN-DO (Protocol): an object qualifies by having the right methods, no inheritance required — Python's duck typing. typing.Protocol formalises this for type checkers. Decision rule: start with composition; use inheritance only for true IS-A; use Protocol for interfaces you don't own.

# Encapsulation — guard invariants with @property
class Temperature:
    def __init__(self, c): self._c = c
    @property
    def celsius(self): return self._c
    @celsius.setter
    def celsius(self, v):
        if v < -273.15: raise ValueError("below absolute zero")
        self._c = v

# Abstraction — ABC forces contract implementation
from abc import ABC, abstractmethod
class Repo(ABC):
    @abstractmethod
    def find_by_id(self, id: int): ...
    @abstractmethod
    def save(self, entity): ...

# MRO: C3 linearization — use super(), NEVER Parent.method(self)
class A: def greet(self): return "A"
class B(A): def greet(self): return super().greet() + "→B"
class C(A): def greet(self): return super().greet() + "→C"
class D(B, C): pass   # MRO: D→B→C→A→object
assert D().greet() == "A→C→B"   # C3 ensures A is visited once

The __eq__/__hash__ contract — the most dangerous

Override __eq__ without __hash__ → Python sets __hash__ = None (instance becomes unhashable). Define both inconsistently — or mutate a field used in equality after insertion into a dict/set — and lookups silently miss entries while they occupy memory. Value objects must be effectively immutable for the fields that define equality.

# Generator pipeline — each step lazy, O(1) memory throughout
def pipeline(path):
    lines  = (l.strip() for l in open(path))        # read lazily
    parsed = (json.loads(l) for l in lines)          # parse lazily
    valid  = (r for r in parsed if r["active"])      # filter lazily
    return valid                                        # still lazy

# send() — two-way channel; foundation of async/await
def coroutine():
    received = yield "ready"    # suspend; yield "ready", receive sent value
    yield f"got: {received}"

gen = coroutine()
next(gen)                      # prime: run to first yield
result = gen.send("hello")    # inject "hello", receive "got: hello"

Decorators — Full Reference

# Level 1: simple decorator
def timed(fn):
    @functools.wraps(fn)              # preserve fn.__name__, fn.__doc__, etc.
    def wrapper(*args, **kwargs):
        t = time.perf_counter()
        result = fn(*args, **kwargs)
        wrapper.last_ms = (time.perf_counter()-t)*1000
        return result
    wrapper.last_ms = 0.0; return wrapper

# Level 3: parameterised decorator factory
def retry(times=3, on=(Exception,)):
    def decorator(fn):              # level 2: receives the function
        @functools.wraps(fn)
        def wrapper(*a, **kw):      # level 3: replaces the call
            last = None
            for _ in range(times):
                try: return fn(*a, **kw)
                except on as e: last = e
            raise last
        return wrapper
    return decorator

# Stacking — applied bottom-up, executed top-down
@retry(times=3)
@timed
def fetch(url): ...   # call order: retry wrapper → timed wrapper → fetch

# Class-based decorator — stateful via __init__ / __call__
class RateLimit:
    def __init__(self, max_per_sec): self.rate=max_per_sec; self.calls=[]
    def __call__(self, fn):
        @functools.wraps(fn)
        def wrapper(*a,**kw):
            now = time.time()
            self.calls = [t for t in self.calls if now-t < 1]
            if len(self.calls) >= self.rate: raise RuntimeError("rate exceeded")
            self.calls.append(now); return fn(*a,**kw)
        return wrapper

Context Managers — Complete
__enter__/__exit__ · @contextmanager · suppress · ExitStack · async

# Three approaches to the same resource guard
# 1. Class (most explicit)
class Tx:
    def __enter__(self): self.log=["BEGIN"]; return self
    def __exit__(self, exc, *_):
        self.log.append("ROLLBACK" if exc else "COMMIT")
        return False   # NEVER return True (would suppress the exception)

# 2. @contextmanager (concise)
@contextmanager
def transaction(conn):
    try:
        yield conn
        conn.commit()
    except:
        conn.rollback(); raise   # ALWAYS re-raise unless you mean to suppress

# 3. ExitStack — dynamic number of managers
with ExitStack() as stack:
    files = [stack.enter_context(open(f)) for f in paths]
    # all files closed when the with-block exits, even on exception

# suppress — idiomatic exception swallowing
with suppress(FileNotFoundError):
    os.unlink("/tmp/maybe-exists")  # no try/except needed
🧠 Mental model — descriptor lookup priority & __slots__

Attribute lookup priority for obj.attr: ① data descriptor in type(obj).__mro__ (defines both __get__ and __set__/__delete__) → ② obj.__dict__["attr"] → ③ non-data descriptor in type(obj).__mro__ (only __get__) → ④ AttributeError. @property is a data descriptor — it always wins over the instance dict. Instance methods are non-data descriptors — they can be shadowed. Use __set_name__ so a descriptor knows which field it manages. __slots__: replaces the per-instance __dict__ (~200 byte overhead) with a fixed C array (~56 bytes). Saves ~70% memory for millions of small objects. Trade-off: no dynamic attributes; subclasses must also declare __slots__ or savings evaporate. Metaclass preference: try __init_subclass__ first (handles 90% of cases), reach for a full metaclass only for framework-level class-body hooks.

class PositiveFloat:

Interview Bank — 30 Questions
Junior · Senior · Staff / Architect — with model answers and follow-ups
🏆

Junior Level

Q1 · What is the difference between a list and a tuple? When would you choose one over the other? Junior

Both are ordered sequences. A list is mutable; a tuple is immutable and hashable (if all elements hashable). Choose tuple for: data that shouldn't change after creation (records, coordinates), dict keys, multi-return values, and when you want callers to know the structure is fixed. Choose list when you need append/remove/sort. As a bonus, tuples have slightly lower memory overhead and faster iteration.

Q2 · What is the difference between == and is? Junior

== compares value (calls __eq__); is compares identity (same object in memory). Use == for values; use is only for singletons: None, True, False. The trap: CPython caches small ints (−5..256) and interns short strings, so is happens to work — until the value falls outside the cache range.

Q3 · What are Python's falsy values and why do they matter? Junior

Falsy: None, False, 0, 0.0, 0j, "", b"", [], {}, set(), range(0). Anything else is truthy. Matters because Python evaluates any object in a boolean context (if-statement, while, and/or). Writing if items: is more Pythonic than if len(items) > 0:. Custom classes can opt in by implementing __bool__ (or __len__ as fallback).

Q4 · Why is def f(x, items=[]) broken? Junior

Default arguments are evaluated once at function-definition time and stored on f.__defaults__. The same [] is reused on every call — accumulating state across callers silently. Fix: def f(x, items=None): if items is None: items = []. Root cause: the object/reference model — the default is a name binding to one shared object, not a fresh allocation.

Q5 · What does for…else do? Junior

The else runs only if the loop finished without hitting break. Classic use: search loops. Without it you need a separate found-flag. With it: for n in candidates: if pred(n): winner=n; break / else: winner=None. Works the same on while loops.

Senior Level

Q6 · Python is pass-by-value or pass-by-reference? Senior

Neither. Python is call-by-object-reference (call-by-sharing). The function receives a reference to the same object, but the parameter is a new binding. Mutating in-place (lst.append()) is visible to the caller; rebinding (lst = new) is not. Design rule: never mutate arguments you don't own; return new values or document the mutation contract.

Q7 · Explain generators vs lists for a 100M-row stream. What is back-pressure? Senior

A list materialises all 100M rows into RAM (8–80 GB). A generator yields one row at a time in O(1) memory. Back-pressure: because nothing is produced until the consumer calls next(), a slow consumer automatically throttles the producer — no explicit buffering or flow-control code needed. Trade-off: generators are single-pass and not indexable. Use a list when you need random access or multiple passes.

Q8 · What is the __eq__/__hash__ contract and what fails if you break it? Senior

The contract: a == b ⇒ hash(a) == hash(b). A dict/set places an object in a bucket based on its hash. Override __eq__ without __hash__ → Python sets __hash__ = None (unhashable). Define both inconsistently, or mutate the field used in hashing after insertion: the object is in one bucket, but future lookups hash to a different bucket — the entry exists but is unreachable. Silently lost data.

Q9 · Explain the LEGB rule, closures, and the late-binding trap. Senior

LEGB: Python resolves a name starting in Local, then Enclosing, then Global, then Built-in scope. A closure captures a variable from the enclosing scope — not its current value. The late-binding trap: [lambda: i for i in range(3)] — all three closures share the same variable i; when called later, i == 2 for all. Fix: default argument lambda i=i: i creates a new local binding per iteration. Same root cause as the mutable default trap.

Q10 · How does super() work in multiple inheritance? Why is calling Parent.method(self) wrong? Senior

super() returns a proxy that delegates attribute lookup to the next class in the MRO (C3 linearization), not necessarily the direct parent. Hard-coding Parent.method(self) in a mixin skips the MRO and can call the same ancestor twice or skip a class entirely. In cooperative multiple inheritance, every class must call super() so each ancestor is visited exactly once in MRO order.

Q11 · What is the descriptor protocol and how does @property use it? Senior

A descriptor is an object with __get__/__set__/__delete__. Python's attribute lookup checks the class hierarchy for data descriptors (those with __set__) before checking the instance __dict__. @property is a built-in data descriptor — writing obj.x = val invokes property.__set__(obj, val) instead of storing in obj.__dict__. This allows validation and computed attributes. The benefit of custom descriptors: write the validation once, reuse across all fields and classes (DRY).

Staff / Architect Level

Q12 · Explain CPython's memory management. When does weakref help? Staff

CPython uses reference counting (immediate free at count zero — no GC pause) plus a cyclic garbage collector (breaks reference cycles refcounting can't see). weakref helps when you want to observe or cache an object without owning it: a WeakValueDictionary entry disappears automatically when the last strong owner is dropped — preventing the "long-lived dict keeps objects alive forever" memory leak. Use weakref for caches, observer lists, and parent↔child back-references you don't intend to own.

Q13 · What does yield from do that a plain for/yield loop cannot? Why does this matter for async? Staff

Three things: (1) forwards .send(val) into the sub-generator; (2) forwards .throw(exc); (3) captures the sub-generator's return value. A manual loop can only forward values via next(). This matters for async because await expr is mechanically yield from expr.__await__() — the event loop calls .send(None) to advance coroutines; yield from passes that through every layer of the async call stack transparently.

Q14 · Your service leaks memory slowly. RSS grows by 50 MB/hour. How do you diagnose? Staff

Step by step: (1) tracemalloc.start(); ... snapshot = tracemalloc.take_snapshot() — find which lines are allocating most. (2) gc.get_count() — if generation 2 is growing without bound, reference cycles are accumulating. (3) objgraph.show_most_common_types() — identify the leaking type. Common causes: module-level dict holding strong references to large objects; observer patterns without weakref; closures capturing large local variables. Fix: WeakValueDictionary, weakref.ref for back-references, explicit del in long-lived loops.

Q15 · When would you use a Protocol instead of an ABC? Staff

Use Protocol when defining the shape of a dependency you consume, especially across package boundaries or with third-party types you can't modify — zero coupling. Any existing class with the right methods satisfies it; test fakes are plain classes with no imports. Use ABC when you own the class hierarchy, want shared implementation in the base, or want an instantiation-time error for incomplete implementations. Senior phrasing: "Protocol for what I consume; ABC for what I own."

Q16 · Design a type-safe event bus in Python using modern language features. Staff

(1) Generic[E] + Protocol — Handler[E] is structurally typed; any callable with def __call__(self, e: E) -> None satisfies it. (2) Decorator factory — @bus.on(OrderPlaced) registers at class definition time. (3) @dataclass(frozen=True) for events — immutable, hashable, thread-safe. (4) WeakValueDictionary for handlers — prevents the bus from keeping handler objects alive after their owners are GC'd. Result: a fully type-checked, memory-safe event bus in ~40 lines.

Q17 · You need to process 10 M objects/sec with minimal memory. Walk through your Python optimization strategy. Staff

Ordered steps: (1) Measure first — sys.getsizeof(), tracemalloc; confirm the object is the bottleneck. (2) @dataclass(slots=True) (Python 3.10+) — removes __dict__, ~50% memory saving, no call-site changes. (3) numpy structured array — contiguous C memory, 8–16 bytes per record vs 200+ for a Python object. (4) Cython or Rust extension — zero-overhead typed structs if numpy isn't enough. (5) Benchmark end-to-end — I/O or GC pressure often dominates; memory layout gains may not matter if you're I/O bound.

Gotchas Checklist

⚡ Before any Python interview — can you explain all of these from memory?
  • Mutable default argument (def f(x, a=[])) is shared across all calls — use None sentinel.
  • Aliasing: b = a on a mutable shares mutations; copy (a[:]) or use immutables at boundaries.
  • __eq__ without __hash__ → unhashable; both inconsistent → silent dict/set corruption.
  • Generators are single-pass; consuming twice yields nothing. Use itertools.tee or materialise.
  • Late-binding closures: lambda: i captures the variable, not the value. Fix: lambda i=i: i.
  • Forget @functools.wraps → decorator erases __name__, __doc__, signature (breaks FastAPI, Pydantic).
  • __exit__ returning truthy suppresses exceptions — almost always wrong in production.
  • Reference cycles + long-lived dicts = memory leak. Use weakref.WeakValueDictionary.
  • -10 // 3 == -4 (floor division toward −∞), NOT -3 (C/Java truncation).
  • 0.1 + 0.2 ≠ 0.3. Use math.isclose() or decimal.Decimal for money.
  • round(2.5) == 2 (banker's rounding to nearest even) — not 3.
  • Hard-coding Parent.method(self) breaks cooperative multiple inheritance — always use super().
  • list.pop(0) is O(n) — use collections.deque.popleft() for O(1).
  • Type hints are transparent at runtime — they don't validate. Validate at system boundaries with Pydantic.
  • eval/exec on untrusted input is a remote code execution vulnerability.

Three Real Incidents — Python Concepts in Production

🔥 Incident 1 — Mutable Default: 340 Teams Affected

A helper initialises pipeline run metadata. Works in staging. In production: User A's build metadata appears in User B's results. A def init_run(repo, metadata={}) default shares ONE dict object across all calls. A 2AM hotfix. The fix: def init_run(repo, metadata=None): if metadata is None: metadata = {}

# ✗ BUG — one dict shared across all calls, accumulates state
def init_run_BAD(repo: str, metadata: dict = {}):
    metadata["repo"] = repo; return metadata

# ✓ FIX — sentinel pattern; fresh dict per call
def init_run(repo: str, metadata: dict | None = None):
    if metadata is None: metadata = {}
    metadata["repo"] = repo; return metadata
🔥 Incident 2 — Bare except: Payment Failures Silenced for 6 Hours

A bare except: block swallowed payment failures and returned HTTP 200. Builds appeared to start but billing never happened. except: catches SystemExit, KeyboardInterrupt, and every exception — including the payment error that should have been surfaced. Fix: always catch specific exceptions; let unknown ones propagate.

# ✗ SILENT FAILURE — lie to the caller about what happened
try: charge(amount)
except: return {"status": "success"}   # payment failed but we return 200!

# ✓ FIX — specific exception; unknown ones propagate to on-call alert
try: charge(amount)
except PaymentDeclined as e: return {"status": "declined", "reason": str(e)}
except ConnectionError: raise   # infrastructure failure — surface it
🔥 Incident 3 — Aliasing: Middleware Corrupted the Config Cache

Tracing middleware added request_id to every pipeline config. Pipeline configs in the database started having request_id fields. The middleware mutated the dict it received — which was the SAME object stored in the cache. Fix: copy before mutating.

# ✗ BUG — mutates the cached dict object
def add_tracing_BAD(config: dict, req_id: str):
    config["request_id"] = req_id; return config   # cache now has request_id!

# ✓ FIX — new dict; original cache entry untouched
def add_tracing(config: dict, req_id: str):
    return {**config, "request_id": req_id}
